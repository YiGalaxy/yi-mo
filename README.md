# 亿墨 YI-MO

> 本地优先、零注册、Agent 增强的开源小说创作工作台。

双击启动脚本，浏览器打开就是一个编辑器。没有账号，没有云，没有上传。你的书就是你磁盘上的一个文件夹。

```
启动脚本  →  Spring Boot 服务（127.0.0.1:8080）  →  自动打开浏览器

浏览器
┌──────────────────────────────────────────────┐
│  亿墨 YI-MO                           ⚙      │
├─────────┬──────────────────────┬─────────────┤
│ 项目    │  第一章 雪夜          │ 知识库      │
│ ├ 剑来  │                      │  人物 12    │
│ └ 长夜  │  他站在城头，看雪落下 │  伏笔 3     │
│         │  来。                │             │
│ 大纲    │                      │ 批注 15     │
│ 人物    │  ~~~~ ← 错字/语病    │  错字 12    │
│ 正文    │                      │  语病 3     │
└─────────┴──────────────────────┴─────────────┘
```

## 核心理念

**1. 你的稿子首先是你的文件**

所有内容以 Markdown 明文存储，用 YAML frontmatter 承载结构化字段。你可以用 Obsidian、Typora、VS Code 打开，可以 `git commit`，可以 `grep`，可以写脚本批量处理。删除亿墨，你的书还在，一个字不少。

书本体的位置不因软件而改变——后端直接读写你指定的文件夹，没有浏览器沙箱，没有导入导出，没有格式转换。

**2. Agent 永远不动你的稿**

所有 AI 产出都是**提案（Proposal）**：错字以波浪线标注、人物卡以 diff 形式展示、润色以对照视图呈现。作者点"接受"才落盘。没有静默改写，没有自动覆盖。

**3. 便宜的问题不要用贵的办法**

中文错字里有七成是「的/地/得」「在/再」「他/她」这类高频混淆。内置规则引擎纯 Java 实现，毫秒级、零成本地抓掉这一层。LLM 只负责真正需要理解语义的部分。

## 功能

| 模块 | 能力 |
|---|---|
| 项目管理 | 书库文件夹 = 磁盘目录；每本书一个文件夹；卷/章树形管理 |
| 正文编辑 | 富文本所见即所得，Markdown 落盘；专注模式；自动保存；版本快照 |
| 大纲 | 卷/章两级结构，拖拽排序，卡片式情节点 |
| 人物与设定 | 人物卡、地点、物品、组织、术语；别名系统；关系图 |
| 知识库 | 从正文自动抽取实体与关系，人工确认后入库；跨章检索 |
| 校对 | 两级：规则引擎（即时/免费）+ LLM（语义级）；行内波浪线标注 |
| 一致性 | 人物矛盾、时间线冲突、设定互斥、视角漂移、伏笔未回收 |
| Agent | 多模型接入；工具调用式对话；所有产出均需确认 |
| 导出 | Markdown / TXT / DOCX / EPUB |

## 技术栈

**前端** Vue 3 · TypeScript · Vite · Tiptap · Pinia · Naive UI · Tailwind CSS

**后端** Java 21 · Spring Boot 3 · Spring AI · MyBatis-Plus · HanLP · MySQL 8

**预留** Python · FastAPI（语义检索、本地模型，见 `03-agent-design.md` §11）

无账号。无遥测。无云依赖。服务只监听 `127.0.0.1`，稿件不出本机。

完整论证见 [技术选型](docs/05-tech-stack.md)。

## 许可证

AGPL-3.0。选择它而非 MIT 的原因：本项目的数据格式规范（`docs/02-library-format.md`）意在成为通用契约，AGPL 允许任何人自建服务，但要求衍生服务同样开源，避免有人拿这套格式做闭源云服务再回过头来锁定作者。
